# ComfyUI-H3-Scene-Batch

個人用のH3シーン保存・バッチ実行カスタムノードです。
シーン保存は固定のノードIDと接続構成に依存しています。
任意のワークフローには対応していません。

- **H3 Scene Capture**: シーン保存とバッチ生成を切り替えます。同じノードでフォルダ・開始シーンを指定し、総件数・実行位置・今回の完了件数を確認できます。開始シーンは1始まりです。
- **H3 Scene Batch Load**: 既存ワークフロー向けの読み込みノードです。Captureからバッチ生成する場合は操作不要です。
- **H3 Scene Image Path / Audio Path / Video Path**: 指定したファイルを読み込みます。

保存先は `project_dir` で指定します。`scenes.json` と参照素材が保存されます。
バッチ生成も同じフォルダの `scenes.json` と `images` を使用します。Captureに出力端子はありません。バッチ用データは実行時に渡すため、画面上のノードや配線の追加は不要です。

バッチはワークフロー全体の成功後に次のシーンへ進みます。中断・エラー時は未完了のシーンを保持します。
旧JSONのseedが外部ノードへの接続情報になっている場合は、読み込み時に固定seed `4` を使用します。数値のseedと元JSONは変更しません。
自動実行中はブラウザを開いたままにしてください。再読み込み後も任意の開始シーンを指定できます。

複製版 `video_minimax_h3_multimode_scene_batch.json` では、Captureの「生成モード」でR2V／I2V／L2V／FL2Vを選べます。I2Vは画像1を始点、L2Vは画像1を終点、FL2Vは画像1・2を始点・終点として使用します。不要な画像・音声ノードは非表示になります。参照音声はR2Vのみです。

シーン作成で実行し、良かった結果を保存してください。同じJSONに各モードを混在させてバッチ生成できます。複製版で保存したシーンはモデル・LoRA・step数などの生成設定も復元します。R2V用と始点・終点用のモデル設定は切り替え時に保持され、生成側で変更できます。旧シーンはR2Vとして現在の生成設定を使用します。モデル・LoRA（強度を含む）・step数を変更すると、変更した項目だけがバッチにも自動反映されます。設定を使い分ける操作は不要です。変更判定の基準は初回読み込み時の値で、基準はワークフローに保持されます。R2V用と始点・終点用の設定はそれぞれ比較し、変更していない項目には各シーンの保存値を使います。保存済みのシーンJSONは書き換えません。

## カット連結

複製版 `video_minimax_h3_multimode_scene_cuts.json` では、Captureの「カット数」で1〜4を選べます。カット2〜4の指示（Llama-cpp）・秒数・Promptは常に表示され、使わないカットはバイパスされます。2以上の時は、カット2以降の指示と秒数を使い、ComfyUI-H3-Motion-Context-MultiRef の延長と同じ仕組みで全カットを1回の実行でつなげて1本の動画にします。1の時は従来どおりの単発です。

保存は従来どおり「直前の成功シーンを保存」です。カット2以降のPromptと秒数は `extra_cuts` として同じシーンに保存され、バッチ生成でも同じカット数・同じモードでつなげて生成します。I2Vの始点画像は最初のカット、L2V・FL2Vの終点画像は最後のカットに使います。
「実行内容」で「カットNのPromptだけ」を選ぶと、そのカットのLLM以外がバイパスされ、Promptだけを作ります。「動画生成」では作ったPromptをそのまま使い、そのカットのLLMはバイパスされます。指示文を書き換えたカットはLLMが有効に戻ります。

## H3 Scene Director

`user/default/workflows/video_minimax_h3_scene_director_dev.json` は、元workflowを保持した開発用コピーです。
ComfyUIを再起動し、ブラウザを再読み込みしてこのJSONを開いてください。
開発版から旧Load Image 9個・Load Audio 2個、旧LLM・旧バッチ等の不要ノード48個と旧グループを削除しています。素材とPromptの入力はDirectorに集約し、モデル・サンプラー・Context-Loopの生成経路と既存Noteを残しています。

### 操作

1. **H3 Scene Director #1200** の「作成」でプロジェクト名・シーン名を指定します。モードは元Directorと同じ横並びの **T2VA / I2VA / FL2VA / L2VA / REF2VA** ボタンで選びます（保存データでは従来のT2V等の名前を使います）。
2. REF2VAには上から **Image 9枠・Video 3枠・Audio 3枠** の横スクロールレーンがあります。空き枠の「＋」でファイル選択、枠へのD&Dで追加・差し替え、素材を横へドラッグして並べ替えます。レーン選択後のCtrl+V、選択素材のDelete、×での削除に対応します。参照番号は使用する素材の左から順です。I2VAは先頭の画像1枠、FL2VAは先頭・2番目を始点・終点、L2VAは先頭を「Not Used」として2番目を終点に使います。T2VAは入力枠なしです。モードを変えても素材は保持し、同じ画像スロットを使い回します。Promptはノード上で直接編集します。
3. カットのタブを選び、ノード上でPromptと生成秒数を入力します。共通Promptは全カットへ付きます。「カット詳細」でseed・ID・開始／終了状態を編集できます。カット追加にLLMやサンプラーの複製は不要です。
4. 画像欄の「画像をまとめて解析」で未解析・変更画像を解析します。各画像の☰から「この画像を解析」と解析結果の確認・編集ができます。カットタブの日本語指示を入力し、「ストーリー作成」「Prompt作成」「ストーリー→Prompt」でそのカットだけを作成します。Prompt作成は入力済みストーリーを使い、空欄なら日本語指示から直接作成します。成功すると対象カットのPrompt・開始／終了状態を直接更新します。カット1から順に作成すれば、次のカットで前カットの作成結果を参照できます。必要なカットのPromptが揃ったら通常の実行ボタンまたは「このシーンを生成」で生成します。全カットの作成は下部の「補助操作」にあります。
5. 「このシーンを生成」でシーン全体を生成します。完成動画が同じノードに表示され、良ければ「この結果を採用して保存」を押します。編集後でも、保存するのは表示結果を生成した時点のPrompt・seed・使用素材です。
6. 「保存済み・一括生成」でシーンを選び「選択シーンを一括生成」。モード・素材・全カットのPrompt／seedを復元し、モデル・LoRA・sampler・steps・解像度は現在のworkflowを使います。動画生成時にLLMを呼びません。

一括生成中は画面を開いておいてください。エラーで停止した場合や画面を閉じた場合は「未完了から再開」で続けられます。実行中のシーンがあれば、その完了を待ってから次へ進みます。失敗したシーンは先頭カットから再生成し、完了済みシーンは飛ばします。停止ボタンはこのDirectorの実行だけを対象にします。

### 保存内容

保存先は `output/h3_scene_director/<プロジェクト名>/` です。

- `scenes.json`: 採用シーン。各シーンに全カット、実行seed、確定Prompt、生成／重複除去後のフレーム数、モード、素材の役割、生成設定、成功実行ID、実尺を保存します。
- `assets/`: 使用した参照画像・音声・動画のコピー。
- `previews/`: 採用した完成動画のコピー。
- `batch.json`: 今回の一括生成の対象・完了位置・実行ID・結果。

同じ成功実行の二重保存は追加を行いません。生成後に参照ファイルが変更された場合は、その結果の採用保存を拒否します。
各素材は相対パスで保存するため、プロジェクトフォルダを別環境の同じ `output/h3_scene_director/` 配下へコピーして読み戻せます。モデル自体は含みません。
既存Capture用の `scenes.json` は変換しません。Director用プロジェクトとは分離しています。
チェックポイント・潜在はContext-Loopの実行フォルダに残し、採用プロジェクトへはコピーしません。

### 生成と設定

インストール済み **ComfyUI-MiniMaxH3-Context-Loop** の公開ノードを使用します。
シーン内は **Hard picture + smooth audio / Generate audio**。前カットの映像39フレーム・音声末尾8tickを使い、映像と音声の重複を一緒に除去します。シーン間には状態を持ち越しません。
始点画像は先頭カット、終点画像は最後のカットだけに適用します。動画参照はVHSで24fpsとして読み込み、指定した場合はその音声も使います。

秒数はoverlap込みです。15秒×2は685フレーム（約28.542秒）、15秒×3は1008フレーム（42秒）です。完成尺への補正はありません。
空欄のseedには接続されたseedノードの値を使い、生成後の採用保存では各カットの実際のseedを固定します。JSON中のuint64 seedは文字列で保存し、桁落ちを防ぎます。
「このシーンを生成」はサブグラフ内・表面に出したseed欄にもComfyUI標準の固定／ランダム／増加／減少と更新タイミングを適用します。カットに直接指定したseedと保存済みシーンのseedは優先されます。
「Plan JSONを読み込む」でJSONの貼り付け、またはファイル選択ができます。貼り付け後は「貼り付けたJSONを読み込む」を押します。不正なJSONや置き換えのキャンセルでは現在のカットを保持します。未編集の追加フィールドは保持します。直接編集したPlanにカット別stepsがあれば試作で使用し、一括生成では現在のstepsで上書きします。
通常のComfyUI実行ボタンも利用できます。run_nameは自動で実行ごとに分け、生成設定と参照内容のfingerprintをContext-Loopへ渡します。Loop Startは開始カット1のまま使います。
完成動画は `output/h3_chains/<自動実行名>/final/`。**H3 Scene Result #1211** が成功結果をDirectorへ戻します。

LLMモデル・mmproj・パラメータは移行元の設定です。「LLM設定」モーダルでseed・最大出力トークン・temperatureを変更でき、workflowに保存します。
画像解析は画像単位で既存Llama-cppの画像キャッシュを使用し、日本語の観察結果を表示します。後続のストーリー・Prompt工程には解析文と現在の参照番号を渡します。解析文は編集して再利用でき、画像内容・役割・メモ・モデル設定等が変わった場合は後続の実行時にも更新します。「解析済み」は保存結果の有無を示し、ファイル内容は実行時に再確認します。画像解析の整理には現在のPrompt用LLM設定を使います。音声・動画は直接解析せずメモを渡します。既存モデルや他パッケージのソースは変更していません。
全体用とカット別の日本語指示・ストーリー、画像ごとの解析文はDirectorのworkflow内に保持します。workflowを保存して引き継げます。カット1は単発としてPromptを作り、カット2以降の「前カットの終了状況をPromptに含める」（初期ON）がONなら、それまでの確定Prompt・開始終了状態と全体ストーリーを文脈として使います。OFFでは対象カットの文章だけを渡します。直前カットのPrompt・終了状態を明示して渡し、終了時点の人物・位置・姿勢・動作等を短く説明してから次の動作へ進むよう指示します。説明は開始状態欄だけでなく、H3用Prompt本文に含めます。生成済み動画を解析する機能ではありません。この設定はLLM専用で、映像・音声の継続設定は変更しません。対象外のカットは適用時に変更しません。
移行前の画像解析文は「以前の画像解析結果」で確認できます。旧モーダルの全体用・カット別の指示とストーリーも保持します。

### 検証範囲

`test_director_dialog.mjs` で画像単位の解析・再利用・同名画像の差し替え・失敗・中止、`test_director_ui.mjs` で画像欄とカット欄のボタン、タブ別の指示保持、前カット参照ON/OFF、Promptの直接反映と実行時の送信内容を検証します。DOMテストは `H3_DOM_MODULE` にlinkedomのESM入口を指定します。キュー応答はテスト用で、実LLM推論ではありません。
Python 32件、JavaScript 7ファイルのテストを実施。保存と読み戻し、混在モード、カット別seed、設定変更、失敗後の再開、実行対象を限定した中止、DOM上の直接入力とタブ切替を確認しました。
seed制御は追加の `test_director_seed_controls.mjs` で外側・内部・入れ子・表面に出した欄と更新タイミングを40条件で検証します。実行にはNode.jsの `stripTypeScriptTypes` と、`H3_FRONTEND_ASSETS` に指定したComfyUI frontendの `static/assets` 内のソースマップを使います。推論は実行しません。
実際のComfyUIを別ポート・CPUで起動し、公開Plan展開→成功履歴→採用保存→コピー済み素材の読み戻しを確認しています。この接続確認の動画はCPUで作った検証用動画で、H3の推論ではありません。
R2Vの15秒×2カット動画は前段階で利用者が確認済みです。今回のH3／LLMの実推論と画面の目視確認は未実施です（ブラウザ検証ツールが確認用URLへの接続を拒否）。
移行直前の開発workflowは `.stage2-backup.json`、それ以前は `.stage1-backup.json` に保持しています。
